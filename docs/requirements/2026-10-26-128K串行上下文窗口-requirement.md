# related-party-identification：128K 串行上下文窗口需求

- 日期：2026-10-26
- 状态：用户已于 2026-10-26 确认；并授权自主完成后续设计文档，实际编码前停止
- 范围：仅上下文装载、独立窗口调度与断点交接
- 本轮工作边界：完成需求、方案设计和实施计划文档后，在实际编码前停止；不进入编码、测试执行或交付改动

## 背景与问题

本技能现有功能可正常工作，但在 128K 上下文模型上，20 维工商资料、候选扩张、工具输出和报告解读若在长对话中反复累积，可能超出上下文。用户要求只降低上下文占用，任何功能、判断、证据和成果均不得因此降级。

## 已确认的用户决定

1. 将“只降低上下文占用，功能和结果绝不降级”作为硬门槛。
2. 技能入口询问本次使用 1M 还是 128K 上下文模型；1M 保持现有执行流程，128K 才进入新增的优化调度路径。
3. 128K 路径可以使用独立对话或独立 Agent 窗口，但必须串行，任何时候只运行一个模型任务。
4. 不借助并行提速，不更换当前模型。
5. 本次不纳入任何 OCR 路线、模型或问题。

## 功能范围

- 在现有技能中增加轻量上下文分流，不建立另一套关联方规则或简化报告流程。
- 128K 路径复用现有任务状态、断点恢复、20 维取数、候选扩张、证据比对和八表报告程序。
- 原始导出文件和完整候选记录留在磁盘；模型只在原流程需要判断或用户确认时取得完整必需内容。
- 需要独立窗口解释或复核时串行执行，完整结果落盘后主控窗口只保留状态和位置。
- 主控窗口本身需要轮换时，从既有任务状态续作，不重复取数或扩大核查范围。

## 明确不做

- 不减少 20 个既定维度、候选公司、穿透层数、证据字段或实际比对范围。
- 不改变持股阈值、100 家和深度确认点、限速、重试、缺口标记及保底通道。
- 不把候选、红旗或自动初判改成最终关联方结论。
- 不减少七类证据、八张工作表、来源链接、人工复核栏或建议审计程序。
- 不更换模型，不新增外部模型服务，不并行查询或调用 Agent。
- 不处理 OCR。

## 约束与失败处理

- 独立窗口必须使用当前对话所用的同一模型；宿主不能保证时，不静默换成其他模型。
- 任一时刻最多一个执行窗口；既有注协请求仍按原流程串行执行。
- 候选超过上限或穿透边界时，用户确认所需的范围和来源不得因上下文优化被省略。
- 单项必需确认内容在当前 128K 环境中无法完整装入时，停止并报告，不通过减少名单或证据硬跑。
- 无法可靠保存或恢复状态时停止，不把缺数据或未比对当作已完成。
- 未通过等价验收的环节不得纳入可用的 128K 路径。

## 验收标准

1. **路由**：入口能区分 1M 与 128K；1M 不进入新调度，128K 不进入并行调用。
2. **串行**：执行记录证明同一时刻最多一个模型任务，注协请求节奏不因新入口改变。
3. **范围等价**：相同输入和状态下，两种路径的取数维度、候选名单、穿透边界、确认点、数据缺口和比对范围一致。
4. **确定性结果等价**：相同原始导出目录下，原路径与 128K 路径形成的命中、风险、证据、来源链接和八表报告内容一致；仅新增的上下文调度元数据可以不同。
5. **实际模型验收**：在同一 128K 模型上以代表性案例运行，报告解读不得遗漏高风险证据、可疑红旗或数据缺口。
6. **上下文目标**：代表性候选规模下不再因原始表和历史对话累积超限；续跑不重复下载已完成维度。
7. **原功能回归**：现有自动化测试、分发包校验和报告验收全部通过；1M 除新增的入口询问外，业务行为不变。
8. **失败不降级**：任务过大、模型不一致、状态损坏或窗口无法隔离时，明确停止，不自动缩小核查范围。

## 调研摘要

- `scripts/related_party_workflow.py` 已有 `TaskState`、逐节点保存和 `resume`，可承接独立窗口续作。
- 主流程 `WorkflowResult` 只包含状态、中文消息、报告路径、候选数量和拒绝输入等简要信息，本身不是主要大数据出口。
- 20 维原始导出、候选记录和八表报告均已有磁盘成果，128K 优化应主要约束模型何时读取哪些内容，而不是重写核查引擎。

## 设计阶段已解决事项

- 宿主支持时前台串行调用当前模型的独立 Agent；不能保证同模型时改用同模型手工独立对话，无法隔离则停止 128K 路径。
- 状态摘要只输出调度所需字段；候选分页按稳定顺序覆盖完整集合，确认和后续取数仍针对原完整名单。
- 等价验证采用同一离线导出目录比较候选、命中、风险、缺口、证据、链接和八表报告；实际 128K 验收另行核对报告解读不下降。
