# 关联方识别输出与误判修复需求

## 背景与问题

用户使用 related-party-identification 对多家公司执行主动发现后，发现以下四项问题：

1. 注协完整维度导出的基础数据被保存在 Windows 临时目录，未与最终核查报告放在同一输出目录。
2. 核查报告“汇总判断”工作表格式错位：真正表头没有表头格式，第一行数据反而使用了表头格式。
3. 输出文件名固定为“关联方核查报告.xlsx”和“主动发现候选清单.xlsx”，连续调查不同公司时不便区分，且存在覆盖或产生无意义时间戳副本的风险。
4. 客户、供应商导出表中的“关联方名称”被错误解释为会计或审计意义上的关联方，导致全部公开客户、供应商被判为红色硬关联。

## 已复现事实与根因

### 原始导出目录

导出器默认通过系统临时目录建立 rpi_export_ 开头的随机暂存目录，完整维度压缩包和解压后的基础数据都留在该目录。工作流生成报告时没有把这部分资料发布到用户选择的输出目录。

### 汇总表格式

汇总表标题位于第 1 行，空行位于第 2 行，表头实际位于第 3 行。现有格式逻辑却把第 4 行当作表头，并从第 5 行开始设置风险颜色，因此产生表头无格式、第一行数据使用蓝底白字、其余数据再使用风险颜色的错位。

### 输出文件名

工作流使用固定名称生成报告和候选清单，只在发现同名文件已存在时追加时间戳，没有把被调查公司名称作为文件名的稳定组成部分。

### 客户、供应商误判

真实导出的供应商表包含“公司名称”“与本公司关系”“关联方名称”“关联理由”等字段。其中：

- “公司名称”是被调查公司；
- “与本公司关系”记录“客户”或“供应商”；
- “关联方名称”记录公开信息中与该公司发生客户或供应商关系的交易对手；
- “关联理由”记录中标公告、采购结果公告等公开信息来源。

该处“关联方”是广义的信息关联对象，不代表会计准则或审计意义上的关联方。现有规则直接把该列所有非空名称写成红色硬关联，属于字段语义理解错误。

## 用户与使用场景

主要用户是使用该技能执行关联方识别的审计人员。用户可能连续调查多家被审计单位，需要每家公司的原始数据、候选清单和核查报告能够成套保存、清楚区分，并且不能把普通公开客户、供应商误报为关联方。

## 功能范围

### 1. 统一成果目录

用户选择输出文件夹后，每家被调查公司的成果统一放在该文件夹内：

- 被调查公司名称_关联方核查报告.xlsx
- 被调查公司名称_主动发现候选清单.xlsx
- 被调查公司名称_注协原始导出

“被调查公司名称_注协原始导出”是子文件夹，保存本次注协完整维度导出的基础数据表，避免几十张原始表与最终报告混放。

已有数据离线核查模式不复制用户原有数据目录，只生成带公司名称的核查报告。

### 2. 修正汇总表格式

- 第 3 行表头使用蓝底、白字、加粗、居中和自动换行格式。
- 第 4 行起的所有数据行按各自风险等级设置颜色。
- 第一行数据不得使用表头格式。
- 冻结窗格应使标题和表头在滚动时保持符合当前布局的可读性。

### 3. 输出文件名包含被调查公司名称

- 核查报告和候选清单的文件名均以被调查公司工商全称开头。
- 文件名中不能用于 Windows 文件名的字符应自动替换，用户不需要处理。
- 同一公司重复运行且同名文件已存在时，保留现有文件，并为新成果追加时间戳。

### 4. 修正客户、供应商字段语义

- 客户、供应商表中的交易对手名称只作为“公开客户或供应商候选”及其来源证据。
- 该字段不直接产生红色、黄色或绿色关联方风险结论。
- 该字段不参与“用户披露差异”计算。
- 候选清单中的发现理由应改为“公开客户关系”或“公开供应商关系”，不得再写“注协标记关联关系”或“导出表内关联标注”。
- 只有命中股权、控制、关键人员、工商指纹、历史痕迹、担保或资源共用等有效规则时，客户或供应商才进入关联方风险报告。

### 5. 文档同步

同步修正技能说明、规则说明、字段映射、用户说明和 README 中关于“注协标记关联关系”“用户披露差异”的错误描述，避免后续智能助手继续按旧语义执行。

## 明确不做的内容

- 不修改浏览器登录路线。
- 不修改查询限速与随机等待策略。
- 不修改默认 2 层、最多 5 层和 100 家候选上限。
- 不把普通客户或供应商自动排除出候选清单。
- 不根据本次修复自动改写已经生成的旧报告。
- 不删除现有 Windows 临时目录或其中的旧任务文件。
- 不新增第三方依赖。

## 约束与风险

- 必须保留任务恢复能力，恢复导出时仍应认领原任务，不能重新上传同一名单。
- 文件名必须兼容 Windows。
- 如果被调查公司名称相同或同一任务重复运行，不得覆盖已有成果。
- 原始导出发布到输出目录后，后续核查和恢复状态应指向实际可见的成果目录。
- 删除错误规则时，不能顺带删除客户、供应商作为主动发现候选的能力。
- 文档、测试和实现必须使用一致的字段语义。

## 验收标准

1. 新运行主动发现任务后，所选输出目录中同时出现带公司名称的核查报告、候选清单和注协原始导出子文件夹。
2. 原始导出子文件夹中可以直接看到本次完整维度基础数据表。
3. 已有数据离线模式只生成带公司名称的核查报告，不复制输入数据。
4. 汇总表第 3 行具有正确表头格式，第 4 行起按风险等级着色。
5. 使用本次真实导出中的 4 家供应商复测时，不再产生 4 条“注协导出客户/供应商表标注关联关系”的红色硬关联。
6. 公开客户、供应商仍保留在主动发现候选清单中，发现理由使用正确的客户或供应商关系表述。
7. 只有其他有效证据命中时，客户或供应商才进入风险汇总。
8. 同一家公司连续运行两次时，第一次成果不被覆盖，第二次成果文件名追加时间戳。
9. 公司名称含 Windows 禁止字符时，仍能成功生成合法文件名。
10. 定向测试、完整单元测试和技能分发校验全部通过。

## 调研摘要与来源

本次问题均通过本机实际代码和真实导出数据复现，不依赖外部事实：

- 真实输出截图确认汇总表格式错位。
- 真实注协供应商表确认“关联方名称”对应公开供应商交易对手，“关联理由”为采购或中标公告。
- 当前规则在该真实导出上稳定产生 4 条红色硬关联，证明误判可复现。
- 当前导出器状态确认完整维度数据位于 Windows 临时目录。
- 当前工作流确认两个成果文件名为固定字符串。

## 待确认项

无。用户已确认采用“报告和候选清单带公司名称，原始数据放在同级公司专属子文件夹”的目录结构。
