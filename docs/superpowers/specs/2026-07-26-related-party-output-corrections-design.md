# 关联方识别输出纠错设计

## 一、目标

本次改造解决四个已经由真实结果复现的问题：

1. 注协完整维度导出的基础数据随最终成果交付，不再只留在系统临时目录。
2. 《关联方核查报告》的表头样式正确应用到第三行，第一条数据从第四行开始按风险等级着色。
3. 两个成果文件和原始导出目录都带被审计单位名称，避免多家公司连续运行时相互覆盖或难以辨认。
4. 公开客户、供应商只作为候选来源，不再被直接误判为“硬关联”或“未披露关联方”。

本次不改变登录方式、查询限速、随机延迟、股权穿透层数、导出接口及依赖清单。

## 二、方案比较

### 方案一：导出完成后复制到成果目录

保持现有注协导出器不变，先在系统临时目录完成下载和解压，再把解压后的表格复制到成果目录。

优点是改动较少。缺点是同一份数据会保留两份，断点续跑时还要处理“复制了一半”的目录，旧临时目录也仍然存在，状态记录容易同时指向临时副本和交付副本。

### 方案二：让导出器直接使用成果目录作为本次暂存目录

工作流先根据被审计单位名称确定唯一的原始导出目录，再把该目录交给注协导出器。上传名单、下载压缩包、解压基础数据和校验公司范围都在这个目录完成。正常运行直接得到可交付的原始数据，不再额外复制。

优点是路径唯一、断点状态清楚、不重复占用空间，而且没有事后搬运失败的问题。需要给导出器增加一个可选目录参数，但保留原有临时目录行为，现有独立调用和测试替身不受影响。

### 方案三：只把下载压缩包放到成果目录

实现最简单，但用户仍然不能直接查看基础表，也不符合“原始导出与报告放在一起”的验收要求，因此不采用。

## 三、选定方案

采用方案二。

工作流只在真实在线导出时传入成果目录；离线复用已有导出目录时不复制用户原文件。导出器新增的目录入口为可选项：工作流未指定时，仍按原行为使用系统临时目录。这样既满足新的交付要求，也保持原有调用兼容。

成果目录结构如下：

- `<公司名称>_关联方核查报告.xlsx`
- `<公司名称>_主动发现候选清单.xlsx`
- `<公司名称>_注协原始导出\`
  - 本次上传企业名单
  - 注协下载的原始压缩包
  - 解压后的完整维度表格

原始导出目录内直接放置解压表格，用户打开目录后无需再进入随机命名的临时文件夹。

## 四、文件命名

工作流只计算一次“安全公司名”，三个成果共同使用。处理规则如下：

1. Windows 文件名不允许的字符统一替换为下划线。
2. 去掉名称末尾的空格和句点。
3. 空名称使用“未命名公司”。
4. Windows 保留名称增加前缀，避免创建失败。
5. 同名成果已经存在时沿用当前机制增加时间戳，不覆盖旧结果。

公司名称过长时保留足够辨认的前部，并为固定成果后缀留出空间。

## 五、数据流与判定边界

在线模式的数据流为：

`被审计单位名称 → 确定成果名称和目录 → 注协完整维度导出 → 提取主动发现候选 → 对候选执行有效核查规则 → 分别生成候选清单和风险报告`

客户表、供应商表的字段语义调整为：

- 表内被审计单位：公开信息所归属的主体。
- “关联方名称”列：该条公开客户或供应商关系的另一方，也就是公开交易对手。
- 关系类型：公开客户关系或公开供应商关系。
- 作用：只扩充候选范围，不形成风险证据。

错误的“注协标记关联关系”规则整体移除，包括硬关联命中、未披露推断、对应报告页签和提示文字。公开交易对手只有在其他独立规则命中后，才会出现在风险报告中。

现有七类有效核查证据继续保留：

1. 股权和控制关系。
2. 关键人员交叉。
3. 联系方式、地址、网址等指纹复用。
4. 股权网络的交叉持股和共同投资。
5. 历史工商关系。
6. 担保、资金占用等资金联系。
7. 人数、社保、场地等异常资源匹配。

## 六、报告格式

汇总页固定布局为：

- 第一行：报告标题。
- 第二行：留白。
- 第三行：表头，使用深蓝底色和白色粗体。
- 第四行及以后：数据，根据各自风险等级应用颜色。

冻结窗口调整为第四行，使标题和表头保持可见，但不冻结第一条数据。其他明细页格式保持不变。

## 七、断点续跑和兼容

在线任务状态继续记录压缩包路径和解压目录。新任务直接记录带公司名的成果目录；旧任务如果已经记录了原临时目录，仍可按旧状态继续，不强制迁移，也不自动删除旧临时文件。

用于测试的导出器仍可通过现有替换入口注入，不要求知道新目录参数。已有任务状态缺少新字段时继续按默认值读取。

## 八、错误处理

1. 原始导出目录创建失败时，立即停止并给出明确中文提示，不生成看似完整的报告。
2. 下载内容不是有效压缩包、解压路径异常或企业集合不一致时，继续沿用现有失败状态。
3. 文件名清理后为空或属于 Windows 保留名称时自动改为可用名称。
4. 客户、供应商表缺列或个别行不完整时，只跳过无法识别的候选行并记录警告，不得把字段错位解释成关联证据。
5. 没有任何有效风险命中时，风险报告仍正常生成空结果，不用公开交易对手填充结果。

## 九、验证策略

先增加会在旧版本失败的回归测试，再修改实现：

1. 用真实字段结构构造客户表、供应商表，验证公开交易对手进入候选清单但不产生任何风险命中。
2. 验证报告第三行拥有表头样式，第四行不再误用表头样式，并检查冻结位置。
3. 验证三个成果名称都包含清理后的公司名，同名时不会覆盖。
4. 验证在线导出直接落在带公司名的原始导出目录，基础表可直接看到；离线模式不复制输入目录。
5. 验证旧导出器调用方式和旧任务状态仍可使用。
6. 运行项目全部自动测试，并使用一份接近真实结构的样例执行端到端核查，检查生成文件、工作表、风险数量和编码。

## 十、迁移与回退

本次不改写历史成果，也不删除过去生成的临时目录。代码修改前统一备份到 `C:\Users\27651\BackUp\` 下的独立时间戳目录并校验。若回归失败，可用该备份恢复本次修改涉及的文件；新生成的测试成果保留在测试临时目录，不覆盖用户现有报告。

## 十一、自检结论

本设计已经把“候选来源”和“风险证据”分开，避免再按注协字段字面含义认定关联方；三个文件命名和原始数据目录使用同一公司名规则；在线、离线、断点续跑和旧状态的边界均已说明。设计不引入新依赖，也不扩大到登录、限速、穿透深度等无关功能。
