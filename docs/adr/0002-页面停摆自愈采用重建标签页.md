# 页面停摆自愈采用重建取数标签页

下载途中取数页面进入后台冻结态（页面停摆）时，自动重建取数标签页并重试该次请求，而不是要求用户全程保持 Edge 前台不动。

背景：2026-10-25 实测确认，标签页 hidden 后页面内定时器与 fetch 回调被挂起，取数调用永不完成；重建标签页立即恢复。用户面对两三小时的长任务，明确选择"支持正常用电脑、技能在后台跑"（方案 A），否决"约定跑任务时别动 Edge"。

考虑过的替代：约定用户不切窗口（约束几乎必然被打破，历史故障即证据）；客户端拉长退避重试（冻结页面不会自愈，只会拉长空转）。自愈失败时（扩展断连、登录失效、Edge 被关闭）不硬撑，暂停并保留已保存进度、给出操作指引。注意：**窗口最小化不是故障**——2026-10-25 实测最小化后新建标签页 0.3 秒正常返回，健康与否以"重建后能否实际取到数"为准，不以可见性论生死。
