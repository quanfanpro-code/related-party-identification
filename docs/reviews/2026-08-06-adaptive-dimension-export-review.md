# 自适应维度导出改造复核记录

## 复核范围

本次复核覆盖行业库维度导出、断点恢复、原始压缩包保留、无数据判定、任务异常暂停、工作流衔接，以及四川江擎航空科技有限公司的真实查询验收。

## 已发现并修复的问题

1. 原流程一次申请全部维度，失败后缺少可控降级路径。现固定查询 20 个关键维度，先按 10+10 执行；失败批次按 5、3、2、1 的粒度自适应拆分，并且同一时间只保留一个活动任务。
2. 浏览器请求与导出器重复执行等待，导致正常请求和轮询节奏过慢。现由浏览器客户端负责 2—5 秒普通等待和 10—20 秒轮询等待，导出器只在成功批次之间增加 15—30 秒停顿。
3. Windows 偶发占用状态文件时可能造成写入失败。现采用原子写入，并仅对文件占用类错误作有限重试。
4. 断点续跑曾可能覆盖已有批次压缩包或重复申请已完成维度。现跳过已存在的批次编号，并跳过所有已进入完成或无数据终态的维度。
5. 行业库可能返回多个含糊匹配的下载任务。现不再猜测，立即暂停并保留状态，等待人工核对。
6. 下载文件损坏、企业名称不一致、同名文件内容冲突等情形，现均暂停并保存证据；同名文件只有哈希一致时才允许复用。
7. 行业库工作簿的内部使用区域偶尔标记错误。现重新计算实际数据区域后读取，避免有数据却被误判为空。
8. 缺少某个维度工作簿时，只有统计表中企业集合一致且该维度明确为 0 条，才判定为无数据；统计数大于 0 或证据不足时仍保持待处理。
9. 缓存目录曾被分发包校验误扫。现明确忽略 Git、pytest 和 Python 缓存目录。

## 真实查询验收

- 查询对象：四川江擎航空科技有限公司。
- 20 个固定维度全部取得终态：11 个维度有数据，9 个维度明确无数据。
- 第一组 10 个维度中，发票信息在统计表中明确为 0；第二组 10 个维度正常完成。
- 真实运行早期因当时尚未读取统计表的 0 值证据，额外申请了 4 次发票信息单维度任务。发现后已停止本机遗留进程，并修复共同根因；这些历史任务和压缩包继续保留，不作删除。
- 最终状态共保留 7 个可正常打开的原始压缩包，没有覆盖旧文件。
- 已生成主动发现候选清单 42 条，以及关联方核查报告。
- 核查报告中的企业对命中数为 0，不等于没有关联方；原因是本轮只对被审计单位完成全量 20 维度导出，候选企业尚未逐家补充完整数据。关系线索应以主动发现候选清单和原始股东、人员、投资证据为主。
