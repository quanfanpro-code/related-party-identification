# 128K 串行上下文窗口运行说明

本说明只规定上下文调度如何交接，不替代任何业务规则。20 个核查维度、默认五层穿透、
候选上限与确认点、七类证据、八表报告、注协请求节奏仍以 `SKILL.md` 原正文为准。

## 1. 模式选择与续作

- 每次新任务只询问一次："本次使用 1M 还是 128K 上下文模型？"
- 选择 1M：按 `SKILL.md` 原正文执行，不创建、不读取任何调度文件，业务行为保持现状。
- 选择 128K：按本说明执行；续作窗口从调度状态继承模式选择，不重复询问。
- 没有活动窗口且用户明确要求变更模式时才允许变更；不得重置或改写原任务状态、导出状态和候选记录。

## 2. 串行独立窗口

- 执行窗口必须前台运行、串行调度：同一时刻最多一个活动模型任务，下一窗口必须等上一窗口结果已由原工作流或报告程序接受并保存后才能开始。
- 执行窗口必须使用当前对话正在使用的同一个模型；宿主不能保证同一模型时，不启动自动 Agent，改用同模型手工独立对话交接；无法隔离窗口时停止 128K 路径。
- 取数本来由原程序串行完成，不为了"使用新窗口"额外增加 Agent 调用；只有原流程确实需要模型阅读、解释或复核时才启动执行窗口。
- 主控窗口默认完成 20 次调度后必须轮换（`CONTROLLER_DISPATCH_LIMIT = 20`）；宿主提前发出上下文预警时立即轮换。新主控读取 `交接` 输出和原任务状态续作，不重复取数、不扩大核查范围、不读取旧聊天。

## 3. 简要状态与候选完整分页

- 主控通过 `状态` 子命令读取 `stage/status/message_zh/candidate_count/report_paths/active_dispatch` 等简要字段；不得把含 `candidate_records` 的完整任务状态整体读入对话。
- 到达候选或深度确认点时，完整候选记录仍保存在 `候选发现记录.json` 和原任务状态中；用户确认的范围不得缩小。
- 需要向用户展示候选时用 `候选页` 子命令按页读取：按原集合顺序输出，返回页码、总数和本页原文；所有页面合计必须等于原完整集合，不重复、不遗漏。分页只改变展示，不改变确认对象。
- 用户确认后仍调用原 `resume`，把完整名单交给原程序处理，不能只处理已展示的页面。

## 4. 短回执与导入

- 执行窗口只返回短回执字段：`task_id`、`status`（saved / needs_retry / blocked）、`result_path`、`result_sha256`、`business_anchor_path`、`message`。不得返回整份候选、证据或报告正文。
- 主控收到回执后先由原工作流或报告程序校验、保存；只有原程序接受后才调用 `完成` 登记调度。文件存在不等于业务完成。
- 注协请求节奏完全按 `SKILL.md` 原规定串行执行，不因新入口改变；取数或核查失败完全沿用原 missing、降级、暂停和缺口规则。

## 5. 调度命令

`scripts/串行上下文调度.py` 只使用标准库，命令行子命令：`初始化 / 开始 / 完成 / 状态 / 候选页 / 交接 / 恢复`。

```bash
PY="C:/Users/27651/AppData/Local/Programs/Python/Python314/python.exe"
"$PY" scripts/串行上下文调度.py 初始化 --state-path <任务状态文件> --mode 128K --model-binding <当前模型> --backup-root <备份目录>
"$PY" scripts/串行上下文调度.py 开始 --state-path <任务状态文件> --task-id <任务编号> --packet <原任务文件> --window-id <窗口标识> --backup-root <备份目录>
"$PY" scripts/串行上下文调度.py 完成 --state-path <任务状态文件> --task-id <任务编号> --result <结果文件> --backup-root <备份目录>
"$PY" scripts/串行上下文调度.py 状态 --state-path <任务状态文件>
"$PY" scripts/串行上下文调度.py 候选页 --source <候选发现记录.json> --page 1 --page-size 50
"$PY" scripts/串行上下文调度.py 交接 --state-path <任务状态文件>
"$PY" scripts/串行上下文调度.py 恢复 --state-path <任务状态文件> --task-id <任务编号> --reason <原因> --backup-root <备份目录>
```

- 调度辅助文件 `上下文调度状态.json` 与 `上下文调度记录.jsonl` 生成在 `--state-path` 所在目录，只用于调度，不是业务真相；原任务状态、导出状态、候选发现记录和报告仍是唯一业务依据。
- 覆盖调度状态前脚本自动备份到 `--backup-root` 并做字节校验。

## 6. 异常恢复与停止条件

- 异常中断后，经用户或主控明确确认，用 `恢复` 解除陈旧占用并留痕原因；下一步仍从原任务状态判断，不能凭调度记录猜测完成。
- 出现以下情况立即停止并报告，不得降级硬跑：单个完整逻辑任务（一个公司对、一份完整报告或一份完整候选确认）无法装入执行窗口；不能保证执行窗口使用当前同一模型；无法隔离窗口；原任务状态或输入哈希与锚点不一致。
- 主控窗口即将超限时，完成当前任务的保存和登记后立即 `交接` 轮换，不在中途丢弃未保存工作。
